## Safe local verification plan

Use dependency-injected Supabase/browser/linking ports and synthetic UUIDs/codes/sessions only. No live account creation, sign-in, profile mutation, Like/Save/Remix, uploads or lookup calls during automated checks.

- Assert OAuth initiation requests provider google, exact callback and browser redirect suppression; PKCE uses the existing saved client. Never put Google Client Secret or service_role in app configuration.
- Validate exact callback scheme/host/path, code-only exchange, provider errors, malformed/missing code, cancellation, duplicate/stale callbacks, retry and unmount/background behavior. Reject token-fragment fallbacks and arbitrary return navigation. Never log callback URLs, codes or tokens.
- Exchange a code once; only confirmed session success navigates. Preserve the single SessionProvider observer, AsyncStorage restoration, sign-out and refresh behavior. Preserve existing email signup/confirmation/sign-in tests.
- Test Google from both modes without requiring email/password or registration lookup. Disable competing submissions during browser/exchange work. Existing signed-in users should retain the normal Continue behavior.
- Exercise anonymous/private gating, synthetic owner versus other-user account/private projection checks, unchanged public client isolation and existing intent continuation/cancellation regression tests. New auth must not broaden database or Storage permissions or use Google metadata as authorization.
- Run affected auth/session/profile/intent regressions, typecheck, scoped lint and appropriate native/bundle checks. QA and independent review required before handoff.
- No SQL migration order, database cleanup or rollback is needed because no backend changes are proposed. Local failure recovery: retain email login, cancel browser session, discard stale attempt and retry without automatic duplicate exchange. Clear only attempt-owned state, never unrelated session data.

Physical development-build/APK end-to-end verification remains separate and requires an available device and explicit owner authorization for any live sign-in/account creation and resulting side effects. Verify system browser return, cancel/back, restart persistence, sign-out, network failure and existing-account linking before claiming readiness. Avoid triggering pending social writes during live auth checks unless separately approved. Google normally auto-links eligible same-email identities; use server behavior, not app-side email merges. SAML SSO is excluded from automatic linking.

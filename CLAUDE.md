## Coordination and backend preflight
The main session is Architect: it plans, assigns exclusive paths, delegates, integrates and reports; it may implement small/focused tasks directly under the shared proportional verification policy. One Architect, at most two specialists at once, only the Architect delegates. Specialists never delegate. Read D:/Travel_Mvp/docs/multi-agent-workflow.md when accessible; if unavailable, retain these rules and report the missing context.
Before implementation, record a repository-based backend-impact assessment under the shared workflow. UI-only work with unchanged data/auth/persistence/API/Storage contracts needs no Backend Developer or live check. Backend-impacting or uncertain work requires the full read-only live-schema preflight and safe isolated test plan before affected implementation. Missing required live evidence blocks that path only. Live changes still need separate explicit approval.
For major/sensitive changes, obtain QA and independent review against a stable identified snapshot; for other tasks follow the selected tier, fix findings and rerun affected checks before authorized publication. Report exact files, checks, limitations, unpublished work and approvals needed.

## Check and context budget
Use the shared proportional verification policy for both repositories. Small cosmetic tasks use one session, diff/visual checks and a concise report; focused tasks use affected tests and static checks as needed. Major/sensitive tasks retain specialist implementation, QA and independent review. Do not launch agents, run all checks or load full conversation/repository context by default. Pass compact briefs and relevant paths/evidence; rerun only affected checks after changes. Explicit requests for broader checks take precedence.
